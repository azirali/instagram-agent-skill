# Instagram plan

Turn the user's actual product, audience and available evidence into an achievable editorial plan. Start with an existing brief or source material; ask only for missing facts that change the plan.

## Establish the brief

Use [the brief template](assets/brief-template.md) when no equivalent exists. Separate confirmed facts, proposed positioning, and unknowns. Keep the public name and product spelling consistent. Do not invent clients, revenue, awards, testimonials, release status or growth results.

Choose a concrete audience and objective for this batch, such as qualified product feedback or showing how a feature works. Build pillars around evidence the user can actually provide: a working demo, a design decision, a lesson from a documented release, or a founder's own account of an event.

## Plan a realistic batch

Scale cadence to the user's footage and time. Each entry should specify:

- Audience question, one takeaway, and the source supporting it.
- Format, language and assets needed.
- Opening idea, one relevant call to action, and an observable success measure.
- Preparation status and a proposed date/time with timezone when scheduling is requested.

Do not label a generic posting time as optimal. With account insights, treat time slots as experiments. Without them, suggest convenient test windows and state the assumption.

For RU/EN/KK, adapt separate versions for the intended audience. Preserve names, dates, prices, feature availability and uncertainty. Avoid stuffing three full captions into one post unless the user wants that format. Kazakh copy needs correct letters, including Ә, Ғ, Қ, Ң, Ө, Ұ, Ү, Һ and І where appropriate.

## Deliver

Return a concise positioning statement, the calendar and any factual or asset gaps. Keep unverified claims out of copy ready for publication. The reel, caption, carousel and insights skills in this repository are optional follow-on workflows; they are not required to use this skill.

Planning does not authorize posting, messaging, paid production, scheduling or account changes. Carry forward any specific authorization the user has already given; ask only if an external action is needed and its scope is missing.
